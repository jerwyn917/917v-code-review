# Report guide

The reports are generated by `scripts/render-reports.py` from three inputs:

| File | Written by | Purpose |
|---|---|---|
| `docs/code-review/findings.json` | `validate-findings.py` | Validated, de-duplicated findings with IDs (machine-readable output) |
| `docs/code-review/.work/stack.json` | `detect-stack.py` | Detected technologies |
| `docs/code-review/.work/summary.json` | **the orchestrator (you)** | Narrative sections |
| `docs/code-review/.work/merges.json` | **the orchestrator (you)** | Merge decisions for cross-agent duplicates, from `merge_candidates` (optional) |

## summary.json

```json
{
  "repository": "acme-payments-api",
  "review_type": "Full codebase review",
  "scope_description": "entire repository (412 files)",
  "agents_run": ["architecture-reviewer", "security-reviewer", "performance-reviewer", "backend-reviewer",
                 "database-reviewer", "testing-reviewer", "devops-reviewer"],
  "agents_skipped": [{"agent": "frontend-reviewer", "reason": "no frontend framework or UI component files detected"}],
  "overall_summary": "2–5 sentences: what the system is, overall state, the most important theme.",
  "health_assessment": "2–4 sentences explaining the rating in terms of the findings (cite IDs).",
  "architecture_overview": "Markdown: layers/modules, how requests flow, notable patterns, strengths.",
  "dependency_analysis": "Markdown: module coupling, import cycles found (or none), most depended-on modules.",
  "security_overview": "Markdown: auth model, trust boundaries, main risks (cite IDs).",
  "owasp_notes": {"A01": "Guards on all controllers except /admin/export (SEC-002)", "A03": "Raw SQL in 1 repository (SEC-001)"},
  "strategic_recommendations": [
    {"title": "Centralise authorization", "detail": "Use the existing RolesGuard as a global guard ...", "related": ["SEC-002", "API-004"]}
  ],
  "positive_observations": ["Consistent DTO validation in the orders module"],
  "limitations": ["Static review only: no code was executed", "Dependency CVEs not checked online (no network authorization)"]
}
```

Rules:
- Every claim must trace to a validated finding (cite its ID) or to code you read.
- `strategic_recommendations`: 3–5 cross-cutting themes, ordered by value. They must build on the existing architecture, avoid new libraries unless necessary, and never duplicate a single finding's recommendation verbatim.
- `limitations` must always include: static analysis only, what was not covered (large repo sampling, skipped agents, generated code), and whether dependency vulnerabilities were checked online.
- Keep secrets out.

## Output files

| File | Contents |
|---|---|
| `executive-summary.md` | Summary, health score and rating, counts by severity and category, critical risks, top recommendations, stack, coverage, validation stats, read-only check |
| `detailed-findings.md` | Index plus every finding with all required fields; in diff mode, grouped by on-changed-lines, elsewhere in changed files, and context. Also lists rejected claims, for transparency |
| `security-review.md` | Security overview, OWASP Top 10 table, Security findings, security-relevant findings from other categories, areas checked |
| `architecture-review.md` | Architecture overview, structure, dependency analysis, Architecture and Code Quality findings |
| `recommendations.md` | Strategic recommendations, then actions by priority (1: Critical/High, 2: Medium, 3: Low/Info), positives |
| `dashboard.html` | Interactive dashboard in 917 Ventures branding: amCharts 5 health gauge, severity donut, category, OWASP, hotspot-file and reviewer-heatmap charts that cross-filter the findings list. Loads amCharts from cdnjs and fonts from Google Fonts; review data never leaves the page; HTML-bar fallback offline |
| `.work/chat-widget.html` | In-chat results widget (HTML fragment) for a host's inline visual tool; not a report |
| `findings.json` | Validated findings for tooling and CI |
